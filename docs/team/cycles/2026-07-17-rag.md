# ARIA Team Cycle — 2026-07-17 (directed: RAG, context, browsing, self-coding)

A directed cycle. Instead of the team picking ideas freely, the user asked for
ideas in three specific areas:

1. **RAG — space + context.** Make ARIA's memory/retrieval use less room in the
   prompt and pick better context.
2. **Web-browsing self-sufficiency.** A first step toward ARIA reading the web
   on its own (the eventual Playwright "research for me" experience).
3. **ARIA self-coding.** Let ARIA turn a conversation into its own change
   proposal.

## Phase 1 — ideas → research (complete)

The idea generator worked inside those three lanes. Four ideas were researched
(two in the RAG lane, one each in browsing and self-coding):

- **distance-gated-recall** (RAG · engineering) — stop feeding weak, unrelated
  memories into every prompt. ChromaDB already returns a distance for each
  recalled fact; today it's ignored. Brief:
  `docs/team/research/distance-gated-recall-brief.md`.
- **rolling-conversation-summary** (RAG · engineering) — keep older conversation
  turns instead of silently dropping everything past the last 6. Brief:
  `docs/team/research/rolling-conversation-summary-brief.md`.
- **single-page-reader** (browsing · engineering) — let ARIA read a web page the
  user pastes and ground an answer in it. Brief:
  `docs/team/research/single-page-reader-brief.md`.
- **conversation-to-proposal** (self-coding · product) — turn a chat plus the
  user's intent into an inert "draft a change" proposal file a human reviews
  before anything is built. Brief:
  `docs/team/research/conversation-to-proposal-brief.md`.

## Gate (touchpoint 1) — DECIDED by user

- **① distance-gated-recall — APPROVED, measurement-first.** Ship it turned off
  (`RECALL_MAX_DISTANCE=0.0`, a no-op) so it only *logs* how far apart the
  recalled memories are. A real cutoff gets picked later from that real data.
- **② rolling-conversation-summary — APPROVED → measured → widen the window.**
  The team measured the actual cost first, then chose the simpler, lossless fix:
  widen the verbatim history window from 6 to 16 turns instead of building a
  lossy summary. The lossy digest was parked for very long ("marathon") sessions.
- **③ single-page-reader — APPROVED as a spike → ADOPT-NATIVE.** The spike found
  Anthropic ships a built-in `web_fetch` tool, so the decision was to adopt the
  native tool rather than hand-roll an HTTP fetcher. Shipped switched off by
  default.
- **④ conversation-to-proposal — PARKED.** Thin standalone value this cycle, and
  it competes with reliability/hardening priorities. Revisit next cycle as an
  aria-ideas "mine this conversation" lens — a dev-side tool only, never a
  runtime route.

## Phase 2 — builds (complete)

Four PRs were opened. Alongside the three approved RAG-lane builds, the
approved-and-queued carryover **episodic-recall-panel** was built first.

- **#131 episodic-recall-panel** (carryover, cycle-2 4th item) — owner-scoped Go
  proxy route + a panel that surfaces episodic memory. Security PASS.
- **#132 distance-gated-recall** — recall gated by relevance distance; no-op
  default; logs the distance distribution. Security PASS.
- **#133 rolling-conversation-summary** (branch `team/wider-history-window`) —
  widened the verbatim conversation window 6 → 16 turns (lossless).
- **#134 single-page-reader** — native Anthropic `web_fetch`; inert by default
  (`WEB_FETCH_ENABLED` off); bundled a parser hardening. Security + code review
  PASS.

**Current merge state (as of 2026-07-17):** the user has already merged **#131,
#132, and #133** into `integration`. **#134 is still open**, awaiting the user's
merge. Merging is the user's call.
